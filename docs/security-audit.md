# AI Browser Agent — Audit Findings (69)

> **Historical record.** This is the audit that drove the project's hardening. File names and line numbers refer to the
> code as it was when each item was found, before the move to `src/aiba/` (for example `agent_ui.py` is now
> `src/aiba/server/main.py`). As of the first public release 68 items are fixed, 3 are partly addressed (the reasoning is kept with each), and 3 are
> open because they need live checks with paid API keys or a real desktop session (P1, P2, P5).

Status legend: `[ ]` open · `[~]` partly addressed · `[x]` fixed

Items marked "likely" were not confirmed by running the app. #16 was confirmed against the installed browser-use 0.13.10.

## Security (critical)

- [x] 1. **Any website can control your browser.** `/ws` has no Origin check and no auth. Any page can connect to `ws://localhost:8000/ws`, watch live screenshots and send mouse/keyboard input to a browser holding your LinkedIn session.
- [x] 2. **`GET /settings` returns every API key and the LinkedIn password in plaintext** (`agent_ui.py:1683`), with no auth. Exposed to DNS rebinding or anything that can reach the port.
- [x] 3. **`POST /task` has no auth or CSRF protection.** Any local or cross-origin caller can queue an arbitrary agent task.
- [x] 4. **LinkedIn credentials are handed over for every site.** `_site_sensitive_data` passes a flat dict. browser-use supports domain-scoped `sensitive_data`, and no `allowed_domains` is set. A prompt-injected page could exfiltrate them.
- [x] 5. **Wrong-site credential use.** `_login_page_instructions` is prepended to every task, so on a Google/GitHub login page the agent is told to enter the LinkedIn credentials.
- [x] 6. **`disable_security=True` in the UI session** (`agent_ui.py:1518`). Turns off web security/CORS on a browser with logged-in sessions driven by an LLM reading untrusted pages.
- [x] 7. **`--no-sandbox` passed unconditionally** (`agent_ui.py:1516`). Weakens Chromium's sandbox while rendering arbitrary web content.
- [x] 8. **No prompt-injection defence.** Page text goes straight to an agent that holds credentials and can send connection requests. *Note from #4–7 review: credentials are now domain-scoped, but on linkedin.com itself injected content (a post or message) could still push the agent to type the password into a page field. Scoping can't prevent that. Consider a human-approval step for sends/posts and for typing credentials.*
- [x] 9. **CAPTCHA instruction tells the agent to "wait 5 seconds and try clicking submit again"** (`agent_ui.py:326`). A bot-detection workaround and a likely LinkedIn ToS / account-ban risk.
- [x] 10. **Real secrets sit in plaintext in the project folder.** `.env` holds live keys and the password; `browser_profile/` and `.browser_profile/` (119 MB) hold cookies and `Login Data`.

## Bugs in task and session control

- [x] 11. **`/stop` sets `_session = None` without closing it** (`agent_ui.py:1658`). Leaks a Chromium process; the live stream keeps polling the dead session; later `Agent(browser_session=None)` spawns unmanaged browsers.
- [x] 12. **Any exception in `run_task` closes the session and nulls it** (`agent_ui.py:461`). Live feed, persistent profile and start page are gone until server restart.
- [x] 13. **`/continue` never stores its task in `_agent_task`.** `/stop` can't cancel a continued run; it flips flags while the agent keeps running.
- [x] 14. **Continued tasks nest.** `_last_task` is overwritten with "Continue the task… Original task: …", so a second continue wraps it again and grows.
- [x] 15. **Race: `_agent_running` is set inside the task, not before it starts** (`agent_ui.py:1646`). Two quick submits launch two agents on one session.
- [x] 16. **Self-critique is dead code (confirmed).** `llm.ainvoke(prompt)` receives a `str` but browser-use's signature takes `list[Message]` and returns `.completion`, not `.content`. It throws, `llm.invoke` doesn't exist, and the fallback returns `8, "evaluation unavailable"`. Every non-trivial result scores 8.
- [x] 17. **Retries mask real failures.** A `None` result scores 2 and retries twice, up to 3 × 60 steps of API spend.
- [x] 18. **The retry starts a fresh `Agent`.** It loses the previous attempt's memory but keeps the same dirty browser state.
- [x] 19. **`task_history.json` shows the pattern:** 5 of 18 runs have an empty result, score 2 and 2 retries. The real error (API key, model, format) is never surfaced.
- [x] 20. **Cancelling raises `CancelledError`, which `except Exception` doesn't catch.** The user turn stays in `_conversation_history` with no agent reply and nothing is saved, breaking turn count and role alternation.
- [x] 21. **`_agent_running = False` runs in `finally` before history is saved and broadcast.** A new task can start mid-write.
- [x] 22. **`hit_limit` is detected via `steps >= max_steps and result is None`.** Misses agents that fail on the final step and can misreport them.
- [x] 23. **`int(body.get("extra_steps"))` is unvalidated** (`agent_ui.py:1670`). Bad input returns a 500.
- [x] 24. **`/sessions/{sid}` builds a path from user input** (`_session_path`). `sid` isn't validated, so path traversal is possible on delete.
- [x] 25. **`_new_session_id()` truncates a microsecond timestamp to 20 chars.** Fragile; IDs can collide.
- [x] 26. **`new_session` doesn't cancel or reset a running agent.** It clears history mid-run, so the result lands in the new chat.
- [x] 27. **`_save_current_session` swallows all exceptions.** Disk-full or permission errors silently lose history.
- [x] 28. **The session index is read-modify-write with no lock.** Concurrent saves can corrupt or drop entries.
- [x] 29. **History keeps only the last 200 turns but the title is `history[0]`.** After truncation the title and turn count are wrong.
- [x] 30. **Context prefix feeds `history[0]` plus the last N turns to the LLM as plain text.** An earlier page's content can carry injected instructions into later tasks.

## Settings and .env handling

- [x] 31. **`_write_env` can't clear a value.** Empty strings are dropped, so a key or the LinkedIn password can't be removed from the UI.
- [x] 32. **`_write_env` writes values raw.** Newlines can inject extra env lines; `#`, quotes and spaces in a password get misparsed by `python-dotenv`, and `_read_env` doesn't strip quotes, so the two parsers disagree.
- [x] 33. **`MAX_STEPS` and `CONTEXT_TURNS` are read with `int()` unguarded.** A junk value crashes a run.
- [x] 34. **Model defaults disagree.** `.env.example` says `deepseek/deepseek-chat`; `llm_config.py` uses `deepseek/deepseek-v4-pro`.
- [x] 35. **Default `claude-sonnet-4-5` in code, docs and UI hint is stale.**
- [x] 36. **`get_llm()` uses `os.environ.get` after `load_dotenv()` without `override`.** A stale shell-level key beats the `.env` value.
- [x] 37. **The DeepSeek monkey-patch replaces `litellm.acompletion` globally.** Fragile across LiteLLM versions and hides `response_format` failures; the error-string match at `agent_ui.py:467` is mostly unreachable.

## Dependencies and packaging

- [x] 38. **`requirements.txt` is incomplete.** Missing `litellm`, `anthropic`, `google-genai`; plain `uvicorn` instead of `uvicorn[standard]`; no `pyinstaller`; `playwright` loosely pinned while browser-use is pinned exactly.
- [x] 39. **The `.exe` isn't standalone.** `launcher.py` shells out to system Python with hard-coded `C:\Users\HP\...` fallbacks; the `.spec` bundles no data.
- [x] 40. **No git repo and no `.gitignore`.** `.env`, `browser_profile/`, `build/`, `dist/`, `node_modules/`, `__pycache__` and a 7 MB `.exe` all sit in the root.
- [x] 41. **Three redundant launchers:** `launch.bat`, `launch_silent.vbs`, `launcher.py`. Behaviour differs; the VBS doesn't kill the old instance and the `.bat` isn't silent. **Fixed: `launch.bat` and `launch_silent.vbs` are thin wrappers around `launcher.py`.**
- [x] 42. **Fixed `sleep 4` before opening the browser** in all three launchers. **Fixed: `wait_until_up` polls the server (up / exited / timeout, 90 s) instead of sleeping 4 s.**
- [x] 43. **`launcher.py` kills whatever process listens on port 8000**, not just its own previous instance. **Fixed: only a process whose command line contains `agent_ui` is stopped; anything else gets a 'port in use' message and the launch aborts.**
- [x] 44. **`launcher.py` truncates `agent_error.log` on every start** and never closes the handle. Old crash logs are lost. **Fixed: log is appended (with a start header), handle closed, rotated to `.old` above 200 KB; if the server dies at once its last error lines are shown.**
- [x] 45. **`launcher.log` has no rotation, no encoding, and no health check.** It logs "Browser opened" whether or not the server came up. **Fixed: rotation, UTF-8, dated lines, and a real health check before 'Browser opened'.**
- [x] 46. **`@app.on_event("startup")` is deprecated** (warning in the log). Move to lifespan. **Fixed: `_lifespan` context manager replaces `on_event`.**

## Design and quality

- [x] 47. **`agent_ui.py` is 1,760 lines, ~1,000 of them an inline HTML string.** That string is a legacy fallback superseded by `frontend/dist`; dead code that will drift. **Fixed: the inline HTML is deleted (agent_ui.py 1,760 -> ~910 lines).**
- [x] 48. **The React frontend depends on a built `dist/`.** If missing, users silently get the old UI. **Fixed: no silent fallback; without `frontend/dist` the server logs a warning and `/` returns a 503 page saying how to build.**
- [x] 49. **Live stream takes a JPEG every 200 ms and broadcasts base64 to all clients with no backpressure.** Also polls when no client is connected or no task is running. **Fixed: messages go to all clients concurrently with a 5 s timeout, and live-view frames use a per-client latest-wins slot, so a slow client sees fewer frames but never slows the others or the sender.**
- [x] 50. **`_WSLogHandler` broadcasts every `browser_use` log line to the UI.** Can include page content and typed values; sensitive-data redaction isn't guaranteed to cover them. **Fixed: `ui_feed.py`: allowlist of agent/tool loggers, INFO+, stored secrets and key-shaped strings redacted, lines flattened and capped at 400 chars.**
- [x] 51. **`_dispatch_input` spawns an untracked `create_task` per event.** Mouse-move floods aren't throttled; exceptions are swallowed at debug level. **Fixed: input goes through one ordered, bounded queue with a single worker (moves coalesced); failures are logged once as warnings.**
- [x] 52. **Keyboard handler only forwards `char` and special keys.** Modifier combos (Ctrl+A, Ctrl+V) and IME input don't work. **Fixed for Ctrl/Cmd shortcuts, paste (sent as text), emoji and non-ASCII characters. Still not supported: IME composition (needs a hidden text field) and copying out of the remote page.**
- [x] 53. **Hard-coded Chrome 131 user agent is spoofed while the real Chromium version differs.** A fingerprint red flag; headless against LinkedIn also raises detection risk. **Fixed: the hard-coded Chrome 131 user agent is gone; the real browser's own is used. Headless Chromium still announces itself as HeadlessChrome, which is a detection risk on LinkedIn.**
- [x] 54. **Global mutable state** (`_session`, `_agent_running`, `_paused`, `_conversation_history`) with no lock. Single-user, single-process by accident. **Closed: run state lives in `TaskController` (#11-15); the remaining module globals are only touched from the single asyncio loop, so a lock would add nothing.**
- [x] 55. **`browser_agent.py` and `linkedin_agent.py` duplicate runner logic** with different profile dirs (`browser_profile` vs `.browser_profile`), so a login in one isn't shared. They also bypass every safeguard in the UI path. **Fixed: both CLI runners use the same guard, prompts, settings and `app_paths`. The LinkedIn CLI keeps its own profile from the UI on purpose (Chromium locks a profile to one running browser).**
- [x] 56. **`browser_agent.py` keeps LinkedIn default tasks with no login handling.** `task_draft_post` and `task_send_connection` rely only on the prompt ("Do NOT click post") with no code-level guard, and `send_connection` accepts any `linkedin.com` path, not just `/in/`. **Fixed: profile URLs must match `/in/<name>/`; `browser_agent.py` no longer has LinkedIn tasks; posting/sending go through the approval guard.**

## Added during fixes

> **#31-40 notes.** *Settings (#31-33, #36):* a new `env_store.py` reads and writes the settings file itself, because python-dotenv cannot represent a value ending in a backslash and cuts values at " #". Values are written JSON-escaped and round-trip exactly (fuzz-tested with tens of thousands of random passwords); an empty value now clears a key (from the file *and* the running app); a save is validated as a whole (clear per-field messages in the UI, nothing written if any field is bad); line breaks can't inject settings; the file beats a stale shell variable. *Models (#34, #35, #37):* `providers.py` is the single source of truth (defaults, key names, UI lists); the Claude default is `claude-sonnet-5-5`; OpenAI and DeepSeek now use browser-use's **native** clients, so `litellm` and the global monkeypatch are gone. There is deliberately **no patched fallback**. *Found on the way:* the UI's provider list said `anthropic` where the server only knows `claude` (picking it would have broken every task; old values are still accepted as aliases); the model picker was empty for Claude; the Context-turns slider couldn't reach 0; `.env.example` contained a stray non-UTF-8 character. *Packaging (#38-40):* `requirements.txt` was rewritten from what the code really imports, with the reason for each line (note `playwright` stays: browser-use runs `playwright install chromium` itself when no Chromium exists; `uvicorn[standard]` is needed for WebSockets; `python-dotenv` was dropped because nothing imports it any more); `requirements-dev.txt` and `build_exe.bat` were added. `launcher.py` no longer has hard-coded per-user paths: it finds a Python that actually has the packages (AIBA_PYTHON, project `.venv`, `py -3`, PATH; skips the Microsoft Store stub), refuses to start if `agent_ui.py` isn't beside it, and explains exactly what is missing. It is documented as a **launcher, not a standalone program** (a self-contained build would need to bundle Python, browser-use and Chromium). The rebuilt exe compiled fine but was only written to a scratch folder; your current `AI Browser Agent.exe` is untouched (copy a new one over it with `build_exe.bat` when the app is closed). A git repo was initialised (`main`), with `.gitattributes` and a README; 67 files would be committed and the scan found no keys, email or personal paths (two usernames in test data were neutralised). **No commit has been made.**

> **#21-30 notes.** Chat storage moved into `chat_store.py` (plain files, unit-tested without the app): session ids are validated (`^\d{8}_\d{6}_[0-9a-f]{4,12}$`, so nothing containing `.`/slashes can reach a file path; your existing chats are accepted unchanged); new ids carry 48 random bits (the first version had 24 and collided about once per 5,000 in the same second, caught by a test); every write is atomic (temp file + rename) and the index is locked, so parallel saves can't drop entries and a crash can't leave a half-written file; a corrupt or missing index is rebuilt from the chat files (the bad one is kept as `index.corrupt-*.json`); a save failure is now shown in the chat instead of vanishing; a chat keeps its first turn plus the latest 2,000 entries and its title/turn count no longer drift. **#26/#68:** starting, switching to or deleting the *active* chat while a task runs first stops that task (its "(stopped by user)" note is recorded in the chat it belongs to), and the UI asks for confirmation first. **#21:** the run slot is now freed only after the chat is saved and the result sent. **#30:** earlier answers are fed to the next task labelled as untrusted data, tidied (no angle brackets, one line, capped), and status notes like "(stopped by user)" are no longer fed back; the user's own earlier messages are kept verbatim. Also: the request is saved the moment a run starts (a mid-run close or crash no longer loses it), a stop landing just after the answer no longer adds a second agent turn, and a damaged index entry can no longer break History.

> **#16-20 notes.** Our text-only critique never worked; it is deleted. browser-use already has a *judge* that reviews the whole run (steps + screenshots) and returns a verdict, a failure reason and flags for "impossible" and "hit a CAPTCHA", so that is now the source of truth (`run_outcome.py`). The UI shows **Checked ✓** / **Needs review** (plus the reason) instead of an invented "N/10"; if no check was possible it shows nothing (never a fake score). Retries: only when the finished run's own agent claimed success but the judge says it is not done, not for impossible/CAPTCHA tasks, at most `MAX_RETRIES` (default 1), and they share the first attempt's step budget (the old worst case was 3x the steps). A retry, and Continue after the step limit, are follow-ups to the **same agent** (`add_new_task`), so it remembers what it did and the browser is where it left it; the paused agent is kept and dropped on stop/discard/new chat/new request, and is only resumed if its browser session is still the current one. A run that errors (bad key, model error) is now a *failure with the real error shown*, not an empty answer scored 2/10 and retried twice; `USE_JUDGE=0` turns the extra check off. **#22:** "limit" vs "failed" is now decided properly (a run only counts as failed-at-the-limit if *every* step errored). **Security:** the judge's failure note is LLM output that has read untrusted pages and is fed back as a follow-up, so it is tidied (one line, no angle brackets, capped) and labelled as a hint that cannot change the task. **UI bugs fixed on the way** (they only became visible now): the result handler read the "current bubble" ref inside a deferred state update, so every answer left the "Working..." bubble spinning above a duplicate answer bubble; and an error or Stop never finished the bubble. Continue also no longer builds an unused LLM client.

> **#11-15 notes.** Root cause of #11/#12 was bigger than the audit said: `Agent.close()` kills the shared browser after *every* run unless `keep_alive=True` (confirmed by running it), so each task ended with a dead browser, a blank live view and lost page state, even between retries. Now: `keep_alive=True`; failed or stopped runs never touch the browser; a dead browser is relaunched by `_ensure_session()`; shutdown closes it. New `task_control.py` owns running/paused/stop/continue (#13-15). Extra fixes found on the way: Stop while *paused* used to do nothing and leave the app stuck; Stop pressed early in a run showed "failed" because browser-use's own cleanup raised an unrelated error while unwinding (now recognised as a stop); a crash outside `run_task`'s try (for example a bad `CONTEXT_TURNS`) used to leave the UI on "running" forever (now reported, though the bad value itself is still #33); leftover Chromium from a force-killed server is cleaned at startup (only our profile's browser); tabs are trimmed to 8 between tasks. Side effects on other items: **#20** (a stopped or failed run now records an agent turn, so turns stay balanced), **#21** (the slot is freed only when the run has fully ended), **#23** (`/continue` validates `extra_steps`).

> **#8–10 notes.** #8 is now enforced in code (`action_guard.py`): credentials only go into login fields; sending/posting/connecting/buying/deleting/downloading/signing up, JavaScript, Enter in a message box, Tab-then-Enter, and very long query URLs need a click on an approval prompt (or a hand-off to the user); `file:`/`javascript:` URLs are blocked; and the agent's own browser can't open the control UI (so it can't approve its own prompts) while other local ports stay reachable. **#59** is therefore partly closed: only the app's own port is blocked, other localhost/LAN addresses are still reachable by design. **#40**: `.gitignore` added; still no git repo. **#55**: the CLI scripts now use the same guard and the same data folder; they still duplicate the runner logic. **Approval modes**: `ask` (default), `auto` (for when you're away: approves send/post/connect-style clicks only on the site the task names, declines JavaScript/odd links/uninspectable elements at once, logs every decision in the chat) and `off` (hand-edit only). Choose ask/auto in Settings. *Residual risk in auto mode: injected content on the named site itself (e.g. a LinkedIn post or message) can still cause sends there.* **#9**: the CAPTCHA workaround is gone; the agent uses a real `request_user_help` hand-off.

> #57/#58 were fixed by replacing screenshot polling with Chromium's own screencast (`live_view.py`): the browser pushes frames only when the page changes, and mouse/keyboard go back through CDP `Input.dispatch*`.
